# החלטות, הנחות ושאלות פתוחות

> חלק ממערך המסמכים של [AgentsOrchestrator](../README.md). נקודת הכניסה לעבודה: **[`TASKS.md`](TASKS.md)**.

שלושה חלקים: **ADR** — החלטות שהתקבלו ולמה · **הנחות** — מה הונח בהיעדר תשובה · **שאלות פתוחות** —
מה שצריך החלטה של המשתמש. **כשמשנים כיוון — מעדכנים כאן קודם.**

## חלק א' — החלטות ארכיטקטורה (ADR)

### ADR-001
**Runtime מקומי + UI בדפדפן, ולא דפדפן בלבד** · ✅ התקבל

הבקשה כללה "אולי הכל ירוץ בתוך הדפדפן". נבדק ונדחה כברירת מחדל:

| דרישה | דפדפן בלבד | Runtime מקומי |
|---|---|---|
| חיבור לתיקייה | File System Access API — Chromium בלבד, מגושם ל-100MB | ✅ גישה מלאה |
| הרצת Python | Pyodide — איטי, ללא `subprocess`, חבילות מוגבלות | ✅ Python אמיתי מבודד |
| מקביליות | Web Workers, מוגבל | ✅ תהליכים אמיתיים |
| מפתח API | חשוף בדפדפן, CORS | ✅ לא עוזב את המכונה |
| 100MB אינדוקס | לחץ זיכרון, IndexedDB איטי | ✅ SQLite + FS |

**החלטה:** `apps/runtime` (Node) + `apps/web` (React), הפעלה בפקודה אחת. חוויית "אפליקציית ווב" נשמרת.
**"מצב Lite" בדפדפן בלבד** (העלאת קבצים, בלי תיקייה ובלי סקריפטים) נשאר כאופציה ב-[P12](TASKS.md#p12).

### ADR-002
**מיזוג בקוד דטרמיניסטי, לא בסוכן** · ✅ התקבל

זו הייתה דרישה מפורשת, והיא גם הנכונה טכנית: מיזוג ב-LLM לא דטרמיניסטי, מוגבל ל-64K פלט, יקר, ומאבד
מידע. `Reducer`־ים טהורים ניתנים לבדיקת יחידה ורצים בזמן קבוע.
**LLM נכנס לתפירה רק כשאימות מקומי נכשל, ורק על התפר** ([`PROTOCOLS.md` §8](PROTOCOLS.md#8-reducers)).

### ADR-003
**NDJSON כחוזה פלט, לא JSON יחיד** · ✅ התקבל

עם תקרת פלט של 64K, קטיעה היא תרחיש רגיל ולא חריג. JSON יחיד שנקטע = הכל אבוד. NDJSON שנקטע = זורקים
שורה אחת. מאפשר גם פרסור זורם לסטרימינג ל-UI. המחיר — קצת מטא-דאטה חוזרת — זניח.

### ADR-004
**הקשר ממוטמן נספר במלוא הטוקנים, במחיר מוזל** · ✅ התקבל · ניתן להגדרה

המשתמש הגדיר תקרת **טוקנים**. מטמון מוזיל **כסף**, לא צריכה. ספירה מוזלת הייתה מאפשרת לחרוג פי כמה
מהתקרה שהמשתמש ביקש. שני המדדים מוצגים בנפרד ב-UI. נשלט ב-`ledger.cachedTokensWeight`.

### ADR-005
**תיקון תוכנית ב-JSON Patch, לא ברענון מלא** · ✅ התקבל

תיקון של 2–3 פעולות עולה עשרות טוקנים ולא אלפים, ניתן לביקורת, הפיך, ומאפשר **allowlist של מסלולים** —
כך שמודל לעולם לא יכול להעלות לעצמו את התקציב. כל גרסה נשמרת והדיף מוצג ב-UI.

### ADR-006
**Zod כמקור אמת יחיד לסכמות** · ✅ התקבל

הגדרה אחת → טיפוסי TS (`z.infer`) + ולידציה בזמן ריצה + `responseSchema` ל-Gemini
(`zod-to-json-schema`) + `{{outputSpec}}` בפרומפט. מונע את הבאג הקלאסי שבו הפרומפט מבטיח מבנה אחד
והוולידטור מצפה לאחר.

### ADR-007
**BM25 לקסיקלי כברירת מחדל, embeddings לא** · ✅ התקבל · לבחינה מחדש

לקוד ומסמכים טכניים, אחזור לקסיקלי + מבנה (מפת סמלים, גרף ייבוא) חזק ו**חינמי**. embeddings עולים או
טוקנים (API) או משקל מקומי (מודל). **נכנס רק אם ה-evals יראו פער מדיד** — [P11](TASKS.md#p11).

### ADR-008
**Event sourcing לריצות** · ✅ התקבל

`events.jsonl` בלתי-משתנה כמקור אמת + SQLite כאינדקס. נותן חידוש אחרי קריסה, ניפוי מלא של
"למה הסוכן החליט ככה", הרצה חוזרת משלב, וייצוא ריצה. העלות — כתיבת אירועים — זניחה.

### ADR-009
**`gemini-3.7-flash` כמודל העבודה, מאחורי הפשטת ספק** · ✅ התקבל

הבקשה ציינה "פלאש 3.7" ואומתה: `gemini-3.7-flash` קיים — 1M קלט, **64K פלט**, רמות חשיבה
low/medium/high, ותמיכה ב-context caching. תקרת ה-64K תואמת בדיוק את מה שהמשתמש תיאר.
`LLMProvider` הוא ממשק כדי שהחלפת מודל או ספק לא תיגע בליבה — אבל **מימוש אחד בלבד בגרסה 1**.

### ADR-010
**עברית כשפת ברירת מחדל, i18n מהיום הראשון** · ✅ התקבל

המשתמש עובד בעברית. הוספת i18n בדיעבד היא ריפקטור כואב, ולכן כל מחרוזת עוברת דרך `t()` מיד.
תמיכת RTL היא דרישה מבנית ולא שכבת עיצוב — ראה [`UX.md` §9](UX.md#9-עברית-rtl-ונגישות).

### ADR-011
**Windows הוא יעד מדרגה ראשונה, מאומת מ-P0** · ✅ התקבל · 2026-09-01

המשתמש הבהיר שהרצה על Windows קריטית. בגרסה הראשונה של התוכנית ההתאמה נבדקה רק ב-P12 — כלומר בסוף,
אחרי שכל ההחלטות כבר נצקו. זו הייתה טעות: חלק מפערי ה-Windows הם עיצוביים ולא ניתנים לטלאי מאוחר.

**ההחלטה:** ה-CI רץ במטריצת `windows-latest` + `macos-latest` + `ubuntu-latest` **מ-[P0-T5](TASKS.md#p0)
ובכל PR**. כשל ב-Windows חוסם מיזוג בדיוק כמו כשל בלינוקס. אין "נתקן את Windows בסוף".

זו אינה הדמיה — GitHub Actions מריץ Windows אמיתי, כולל smoke test שמרים את השרת ובודק שהוא עונה.
**זו הדרך היחידה לאמת, מכיוון שהפיתוח עצמו מתבצע על לינוקס.**

### ADR-012
**אפס תלויות נייטיב שדורשות קומפילציה** · ✅ התקבל · 2026-09-01

התוכנית המקורית כללה `better-sqlite3` ו-`keytar` — שתיהן תלויות נייטיב. ב-Windows, prebuild חסר או
לא תואם־ABI מפיל את המשתמש ל-`node-gyp`, שדורש Visual Studio Build Tools. זו חוויית התקנה ראשונה גרועה
עבור משתמש שרק רוצה להריץ את הכלי, ו**כשל התקנה הוא כשל מוחלט** — הוא לא מגיע למוצר בכלל.

| הוחלף | ב- | נימוק |
|---|---|---|
| `better-sqlite3` | **`node:sqlite`** (מובנה ב-Node 22) | אפס תלויות. אומת: עובד ב-Node 22.22 **ללא דגל**, אך מדפיס `ExperimentalWarning` |
| `keytar` | **`@napi-rs/keyring`** | prebuilds ל-`win32-x64/ia32/arm64-msvc`. `keytar` ארכיוני ולא מתוחזק |

**הסתייגות מוצהרת:** `node:sqlite` מסומן experimental וה-API עלול להשתנות בין גרסאות Node. לכן הוא
נעטף מאחורי ממשק צר ב-`driver.ts` יחיד ([P2-T2](TASKS.md#p2)) — אם יידרש מעבר ל-`libsql` או
ל-`sql.js`, זה שינוי בקובץ אחד ולא בשכבת הנתונים כולה.

### ADR-013
**ארגז החול מצהיר על יכולותיו במקום להתחזות** · ✅ התקבל · 2026-09-01

ל-Windows **אין rlimits**, ואין דרך אמינה לחסום גישת רשת לתהליך-בן בלי Job Objects או קונטיינר.
מכיוון שהרצת סקריפטים מקומיים **דלוקה כברירת מחדל** (Q6), זהו פער אבטחה אמיתי ולא אי-נוחות.

**ההחלטה:** `Sandbox` הוא ממשק עם `capabilities` מפורש, ושלושה מימושים —
Linux/macOS · Windows מקורי · Docker. ב-Windows ללא Docker ה-UI מציג באנר קבוע שהבידוד חלקי
ושהסקריפטים יכולים לגשת לרשת, וממליץ על Docker Desktop.

**העיקרון: מוטב בידוד חלש ומוצהר מאשר בידוד חזק־לכאורה.** משתמש שיודע שהסקריפטים לא מבודדים
יכול להחליט; משתמש שחושב שהם מבודדים — לא. פירוט: [`ARCHITECTURE.md` §8](ARCHITECTURE.md#8-הרצה-מקומית-מבודדת-packagestools).

### ADR-014
**שתי תיקוני תלויות שהתגלו בפועל ב-P0, לא הונחו מראש** · ✅ התקבל · 2026-09-01

שני מקרים שבהם המימוש בפועל (עם בדיקה אמפירית, לא ניחוש) חייב סטייה ממה שתועד או הונח קודם:

**1. `zod-to-json-schema` מייצר סכמה ריקה מול Zod v4.** נבדק ישירות: הרצת החבילה על סכמת Zod v4 אמיתית
מחזירה `{}`. הסיבה: החבילה בנויה נגד הייצוג הפנימי של Zod v3 ולא עודכנה. **הוחלף ב-`z.toJSONSchema()`
הילידי של Zod v4**, שמאומת ועובד נכון (`packages/shared/src/schemas/json-schema.ts`). זו לא הייתה
ברירת מחדל שלא נבדקה — הוכחה בהרצה ישירה לפני שנבחרה. "הכלל הברזל" בפתיחת [`PROTOCOLS.md`](PROTOCOLS.md)
עודכן בהתאם.

**2. TypeScript מוצמד ל-`6.0.3`, לא `7.0.2`.** `typescript-eslint` (הגרסה היציבה העדכנית, `8.69.0`)
מסרב במפורש לרוץ מול TypeScript 7 (שגיאה: *"typescript-eslint does not support TS 7.0"*), ומפנה למעקב
[typescript-eslint#10940](https://github.com/typescript-eslint/typescript-eslint/issues/10940). זו לא
אזהרת peer רגילה — זו כשלה קשה. **הוחלט להצמיד ל-6.0.3** (הגרסה היציבה האחרונה לפני 7.0) על פני ויתור
על linting מודע-טיפוסים. **לבדוק שוב מתי `typescript-eslint` מוסיף תמיכה רשמית ב-TS7** — זו הזדמנות
לשדרג בחזרה, לא מצב קבוע.

### ADR-015
**השתקת `ExperimentalWarning` של `node:sqlite` דורשת `removeAllListeners`, לא רק `process.on`** · ✅ התקבל · 2026-09-01

TASKS.md ([P2-T2](TASKS.md#p2)) קבע כ"גמור" ש"האזהרה מושתקת בעלייה". ההנחה הראשונית הייתה ש-
`process.on("warning", handler)` עם סינון ה-`ExperimentalWarning` של SQLite מספיק — **זה נבדק ונכשל
באמפירי**: השורה עדיין נדפסה ל-stderr. הסיבה: ההתנהגות המובנית של Node (הדפסת כל warning) היא עצמה
listener רגיל שנרשם מראש על `process`, ורישום listener נוסף **לא** מחליף אותו — שניהם רצים.

**ההחלטה:** ב-`apps/runtime/src/db/driver.ts`, `installExperimentalWarningFilter()` קורא
`process.removeAllListeners("warning")` **לפני** רישום ה-listener שלנו, שממשיך להדפיס כל warning
אחר (כולל `ExperimentalWarning` שאינו SQLite) דרך `console.warn` — כך שהתנהגות ברירת המחדל של Node
נשמרת עבור כל דבר חוץ מהאזהרה הספציפית הזו. מאומת ב-`driver.test.ts`.

### ADR-016
**`web-tree-sitter` מוצמד ל-`0.20.8`, לא לגרסה העדכנית** · ✅ התקבל · 2026-09-01

ל-[P3-T5](TASKS.md#p3) (RepoMap) הבחירה הברורה הייתה `web-tree-sitter` (WASM, אפס קומפילציה — הנימוק
כמו `node:sqlite` ו-`@napi-rs/keyring` ב-[ADR-012](#adr-012)), עם `tree-sitter-wasms` כמקור לקבצי
ה-grammar המוכנים (TypeScript/TSX/JavaScript/Python) — כדי לא להריץ `tree-sitter-cli build --wasm`
(תלוי Emscripten/Docker) ב-CI.

**זה נבדק ונכשל באמפירי:** `web-tree-sitter@0.27.0` (העדכנית) נכשלת בטעינת קבצי ה-`.wasm` המוכנים
של `tree-sitter-wasms@0.1.13` עם `getDylinkMetadata` error — פורמט ה-ABI של הקבצים המוכנים (שנבנו
מול `tree-sitter-cli` ישן יותר) לא תואם למה ש-`web-tree-sitter` העדכנית מצפה לו. **הוחלף**: הצמדה ל-
`web-tree-sitter@0.20.8` (ה-API הישן, `Parser.Language.load` וגישת `new Parser()` יחיד, לא ה-API
המפוצל של `0.27`) — אומת ישירות: פרסור TS אמיתי, שאילתת סמלים, וחילוץ תקין. `tree-sitter-wasms` עצמה
לא עודכנה מזמן (ה-`devDependencies` שלה מצביעות על `tree-sitter-cli@^0.20.8`), ולכן הצימוד ל-`0.20.8`
הוא לא "גרסה ישנה שרירותית" אלא **הגרסה שבאמת תואמת** את קבצי ה-grammar שנבחרו.

**הסתייגות:** אם/כשתעודכן `tree-sitter-wasms` לבנייה מול ABI חדש יותר, יש לבדוק שוב אם `web-tree-sitter`
עדכנית יותר נטענת נכון — זו לא נעילה קבועה, אלא תואמות שנבדקה ברגע נתון.

### ADR-017
**`capabilities.pathJail: true` לא אוכף בידוד מערכת-קבצים אמיתי — נותר פתוח בכוונה** · ⚠️ מתועד, לא סגור · 2026-09-04

P11-T6's סקירת אבטחה הריצה פנטסט אמיתי (לא רק סקירת קוד) נגד `LinuxSandbox` האמיתי: סקריפט עם
`networkBlocking: true` שעבד בפועל (חסימת רשת אמיתית, מאומתת) **הצליח בכל זאת** לקרוא `/etc/passwd`
ולכתוב קובץ ל-`/tmp` — שניהם מחוץ ל-`stagingRoot` — דרך נתיבים מוחלטים. הסיבה: `resolveWithinRoot`
בודק רק את ה-`cwd` שמועבר ל-`Sandbox.run()` **לפני** ההרצה; שום מנגנון (chroot/mount namespace/
bind-mount) לא מגביל את מה שהתהליך הרץ בפועל יכול לגשת אליו. סקירת קוד (לא אמפירית — אין כאן macOS/
Windows) מראה **אותו דפוס בדיוק** ב-`darwin-sandbox.ts`/`windows-sandbox.ts` — זה פער משותף לשלוש
הפלטפורמות הלא-Docker, לא ייחודי ל-Windows כפי ש-ADR-013 התמקד בו. נוסף ממצא שני: `posix-exec.ts`
מעביר את `process.env` **המלא** של תהליך-האב לתהליך-הבן (כולל `GEMINI_API_KEY`, אם מוגדר כ-env var
בהרצה אמיתית) — Docker לא נפגע (`docker run` לא מעביר env בלי `-e` מפורש). פירוט מלא, הוכחות והמלצות
ב-[`SECURITY_REVIEW.md`](SECURITY_REVIEW.md).

**ההחלטה, לפי בקשה מפורשת של המשתמש:** לתעד את הממצאים במלואם (כולל בדיקות-תיעוד תקועות בקוד,
`linux-sandbox.pentest.test.ts`'s "KNOWN GAP") **בלי** לבצע את התיקון האמיתי (mount namespace + chroot,
הנדסה משמעותית שדורשת אימות זהיר ואין דרך לאמת אותה נגד macOS/Windows בסביבה הזו) ו**בלי** לגעת בקוד
הייצור (`capabilities.ts`, ARCHITECTURE.md §8's טבלה) בסבב הזה — כדי לא לערבב תיקון-הצהרה עם תיקון
מסוכן בלי החלטה נפרדת, ולא לסכן עבודה מקבילה על P11-T7/T8 באותו סבב.

**חשוב לזכור:** תת-מערכת ה-`Sandbox`/`toolsmith` כולה **אינה מחוברת** ל-`apps/runtime` כרגע (אין
`RunLocalTool` מוזרק, אפס `spawn`/`child_process` בקוד הייצור של `apps/runtime`) — כך שאין וקטור
התקפה חי במוצר הרץ **היום**. הפער הופך לחור אבטחה אמיתי **ברגע שמישהו יחבר** את `toolsmith`/`Sandbox`
לזרימת ה-run האמיתית — סעיפים 1–3 ב-`SECURITY_REVIEW.md`'s המלצות צריכים להיסגר **לפני** אותו חיווט,
לא אחריו.

|---|---|---|
| A1 | רמות התקציב (500K/2.5M/5M) הן **טוקנים**, לא דולרים | הגדרות UI + טבלת הרמות. שינוי קטן. |
| A2 | ✅ **אושר ע"י המשתמש:** התקציב חל על **כל שליחת פקודה** (תור אחד), לא על השיחה | — כבר לא הנחה. ראה [Q1](#q1--התקציב-הוא-לתור-או-לשיחה--נענה) |
| A3 | משתמש יחיד, מכונה אחת, ללא ריצה בענן. **המשתמש מריץ על Windows** | מרכזי. גרסה מרוחקת = מוצר אחר. |
| A4 | קלט טיפוסי ≤ ~500MB לתיקייה מחוברת | מעל זה — אינדוקס אינקרמנטלי מחייב. |
| A5 | תוצר טיפוסי ≤ ~50 קבצים לריצה | מעל זה — הרכבה בזרימה ולא בזיכרון. |
| A6 | Python 3.11+ ו-Node 22+ קיימים במכונה | בדיקת סביבה בעלייה + הודעה ברורה לכל פלטפורמה ([P12-T2](TASKS.md#p12)). |
| A7 | כתיבה לתיקייה **כבויה** כברירת מחדל | אם רוצים דלוקה — שינוי ברירת מחדל + אזהרה. |
| A8 | חיבור אינטרנט יציב | יש retry + חידוש; עבודה אופליין אמיתית לא נתמכת. |

## חלק ג' — שאלות פתוחות ⚠️

**אלה השאלות שכדאי לענות עליהן לפני או במהלך המימוש. לכל אחת יש ברירת מחדל שממומשת אם אין תשובה —
אף אחת מהן לא חוסמת התחלת עבודה.**

### Q1 · התקציב הוא לתור או לשיחה? ✅ נענה
**תשובת המשתמש (2026-09-01): התקציב הוא לכל שליחת פקודה** — כלומר לתור אחד.
זו הייתה ברירת המחדל, ולכן התוכנית לא משתנה. 5 הודעות ב"סטנדרט" = עד 12.5M טוקנים מצטברים.
**כפי שמומש:** `Ledger` בהיקף `runId`. מד מצטבר לשיחה קיים **לתצוגה בלבד** ואינו אוכף דבר
([`BUDGET.md` §1](BUDGET.md#1-כפתור-מטרה)).

### Q2 · תקציב בטוקנים או בדולרים?
כרגע: **טוקנים** (הנחה A1), עם $ כנגזרת. הנימוק: מחירי `gemini-3.7-flash` מתוכננים להכפיל
ב-1.1.2027 — תקציב בדולרים ישנה משמעות מעצמו באותו יום.
**ברירת מחדל שתמומש:** טוקנים ראשי, $ משני. מתג להיפוך — משימה קטנה ב-[P9](TASKS.md#p9).

### Q3 · כתיבה לתיקייה של המשתמש — עד כמה אגרסיבית?
כרגע: כבויה כברירת מחדל, ובהדלקה — staging → diff → אישור → כתיבה עם גיבוי.
*שאלה:* לאפשר "מצב אוטומטי" למי שעובד עם git ורוצה זרימה מהירה?
**ברירת מחדל שתמומש:** ידני בלבד בגרסה 1. מצב אוטומטי רק עם עץ עבודה נקי — נדחה ל-[P12](TASKS.md#p12).

### Q4 · מה קורה למחצית ריצה כשסוגרים את הדפדפן?
כרגע: הריצה **ממשיכה** ב-runtime; פתיחה מחדש מתחברת ומשלימה פערים.
*חלופה:* השהיה אוטומטית לחיסכון.
**ברירת מחדל שתמומש:** ממשיכה, עם התראת מערכת בסיום.

### Q5 · שכבת ה-`cheap` — איזה מודל?
משפחת Flash-Lite מתחלפת מהר, ומודלים ישנים יוצאים משימוש בתאריכים קבועים.
**ברירת מחדל שתמומש:** ה-Flash-Lite הזמין העדכני ביותר, נבחר **דינמית** מ-`models.list` בעלייה,
עם נעילה ידנית בהגדרות. אין מזהה מודל קשיח בקוד — [P1-T7](TASKS.md#p1).

### Q6 · הרשאת הרצת סקריפטים — דלוקה כברירת מחדל? ✅ נענה
**תשובת המשתמש (2026-09-01): דלוקה.** זו הייתה ברירת המחדל, ולכן התוכנית לא משתנה.
**כפי שמומש:** דלוקה, עם תצוגת כל סקריפט שרץ ואפשרות כיבוי גלובלי.
⚠️ **אבל** — התשובה הזו הופכת את [Q9](#q9--רמת-הבידוד-ב-windows-ללא-docker-) לשאלה פתוחה חדשה
וחשובה יותר: ב-Windows המקורי הבידוד חלש מהמתוכנן, וסקריפטים דלוקים כברירת מחדל מגדילים את המשמעות.

### Q7 · שיתוף וייצוא ריצות?
לא באפיון. ייצוא JSON קיים ממילא ב-[P9](TASKS.md#p9).
**ברירת מחדל שתמומש:** ייצוא מקומי בלבד. שיתוף — מחוץ להיקף.

### Q9 · רמת הבידוד ב-Windows ללא Docker ⚠️
**השאלה החשובה ביותר שנותרה פתוחה.** ב-Windows המקורי אי אפשר לחסום גישת רשת לתהליך-בן ואי אפשר
לאכוף תקרת זיכרון, בלי Job Objects או קונטיינר ([ADR-013](#adr-013)). הסקריפטים דלוקים כברירת מחדל
([Q6](#q6--הרשאת-הרצת-סקריפטים--דלוקה-כברירת-מחדל--נענה)), כך שהפער אמיתי.

שלוש האפשרויות:

| | חוויה | בידוד |
|---|---|---|
| **א. מריצים עם באנר אזהרה** *(ברירת המחדל)* | חלקה | חלש ומוצהר |
| ב. דורשים Docker Desktop ב-Windows | חיכוך התקנה משמעותי | מלא |
| ג. אישור לכל סקריפט בנפרד ב-Windows | חיכוך שוטף גבוה | בינוני |

**ברירת מחדל שתמומש:** (א) — מריצים, עם באנר קבוע שמצהיר שהבידוד חלקי, וכל סקריפט מוצג לפני
ואחרי ההרצה. Docker מזוהה אוטומטית ומשדרג את הבידוד כשהוא קיים.
**נדרשת החלטה שלך אם** התוכן שתעבד איתו רגיש, או אם המחשב בסביבה ארגונית.

### Q8 · אריזה כאפליקציית דסקטופ?
כרגע: פקודה אחת + דפדפן. Tauri/Electron ייתן אייקון והפעלה כפולה.
**ברירת מחדל שתמומש:** CLI + דפדפן בגרסה 1. אריזה — משימה אופציונלית ב-[P12](TASKS.md#p12).
